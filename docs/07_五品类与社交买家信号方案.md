# 五品类与社交买家信号方案

## 1. 品类范围

正式检索范围扩为：抹茶、蓝莓、刺梨、辣椒、茶。英文词典及排除词由 `pipeline/product_taxonomy_v1.json` 管理。

刺梨必须同时检索学名和海外通用名：`Rosa roxburghii / cili fruit / chestnut rose fruit / burr rose fruit / chinquapin rose fruit`。仅出现 ornamental rose、plant、seed、flower 时排除。

## 2. 社交平台不是直接RFQ库

评论、帖子和视频描述可发现需求，但不能仅凭一句评论认定为B端买家。信号分三层：

| 层级 | 例子 | 可否进入机会表 |
|---|---|---|
| 消费兴趣 | “看起来好喝”“哪里买一盒” | 否 |
| 商业兴趣 | “能否批量供货”“MOQ多少” | 候选，需补企业身份 |
| B2B需求 | “我们是美国分销商，需要每月500kg并要求Organic证书” | 是，但仍需主体和时效验真 |

## 3. 平台接入顺序

| 优先级 | 平台 | 方式 | 定位 |
|---|---|---|---|
| P0 | TikTok | Research API（获批后）查询公开视频与评论 | 需求发现 |
| P0 | YouTube | Data API `commentThreads.list`，按视频和关键词检索公开评论 | 需求发现 |
| P0 | Reddit | 公开帖子/评论或官方API | 需求发现与行业讨论 |
| P1 | TikTok/Instagram/LinkedIn公开页 | 团队授权浏览器会话；不绕验证码和访问控制 | 低频补充 |
| P0 | B2B RFQ/采购门户 | HTTP/API/授权账号Connector | 直接需求主源 |
| P0 | 企业官网、贸易记录、注册信息 | 公开页面/API | 买家主体与能力验真 |

TikTok Research API 的评论接口需要获批项目和 `research.data.basic` scope。没有获批前不使用非官方破解接口抓全量评论。

## 4. 评论信号字段

- `platform / post_url / video_id / comment_id / parent_comment_id`
- `comment_text / published_at / observed_at / language`
- `author_handle / profile_url`（平台公开标识，不等于企业实体）
- `matched_product / product_form / quantity / unit / frequency`
- `intent_phrase / intent_level / buyer_role_claim`
- `company_name_claim / website_claim / country_claim`
- `public_business_channel / contact_gate`
- `consumer_exclusion_hit / spam_score / freshness_score`
- `snapshot_sha256 / evidence_span / extraction_version`

## 5. 买家实体补全

评论作者不能直接写入 `buyer.canonical_name`。按以下顺序补全：

1. 评论/帖子是否明确声明公司、进口商、分销商、零售商或采购职位；
2. 个人资料是否公开链接企业官网或企业主页；
3. 官网域名、公司名、国家和业务范围是否一致；
4. 是否存在公开采购页、企业邮箱、注册信息或贸易记录；
5. 保存所有字段来源和冲突，不猜测被隐藏的公司信息。

只有企业身份可验证后才创建正式 `buyer`；否则保留为 `social_signal_candidate`。

## 6. 社交信号准入分

| 维度 | 分值 |
|---|---:|
| 明确B2B采购动作 | 30 |
| 企业身份可验证 | 25 |
| 数量/规格/频次 | 20 |
| 时间与公开触达入口 | 15 |
| 贸易/采购历史佐证 | 10 |

总分低于70不进入正式机会表。评论单一来源在没有企业证据时不得达到70分。
