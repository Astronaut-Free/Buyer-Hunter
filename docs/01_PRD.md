# 买家猎手 PRD（36 小时 Demo）

## 1. 产品目标

让贵州特色产品卖家在 3 分钟内从平台聚合的海外需求中找到值得跟进的买家：

1. 输入目标产品，并可选填写仅用于匹配的私有供货条件；
2. 查看平台从海外公开来源聚合的候选买家需求；
3. 查看按采购窗口与供需匹配排序的 Top 5；
4. 打开买家详情，看到原始证据、规格匹配、缺口、风险和下一步。
5. 获得原始采购入口或公开业务渠道，自主决定是否联系。

卖家是平台用户；海外买家在 Demo 中是被聚合、验真的需求主体，不需要注册或主动在平台发布需求。卖家填写的供货条件不公开展示，不形成店铺或商品页。

商业模式是卖家会员订阅。免费用户查看有限需求摘要；有效会员解锁完整买家需求、采购入口和经过验证的公开商务联系方式。Demo 预置会员状态，不接真实支付。

### 1.1 北极星指标（Demo 口径）

`可行动机会数 = 通过证据硬门槛、无已证实规格硬冲突、存在可执行下一步的机会数`

不使用“抓取条数”作为核心成功指标。

商业验证指标单列：`会员解锁率`、`解锁→跟进率`、`跟进→有效洽谈率`、`会员续费率`。36 小时只采集前两项演示事件，不伪造成交率。

## 2. 用户故事与优先级

| ID | 优先级 | 用户故事 | 验收条件 |
|---|---|---|---|
| US-01 | P0 | 作为卖家，我能搜索抹茶、蓝莓等目标产品的海外买家需求 | 切换目标产品不改变主流程；抹茶、蓝莓只是样例 |
| US-02 | P0 | 作为销售，我能发起一次信号扫描 | 展示任务状态、来源、成功/失败数量；失败来源不阻塞已有结果 |
| US-03 | P0 | 作为销售，我能看到 Top 5 买家 | 按机会分降序；显示分项分数、Why Now、数据模式 |
| US-04 | P0 | 作为销售，我能核验证据 | 每条核心结论可回链到 URL、时间和原文片段 |
| US-05 | P0 | 作为销售，我能看供需差距 | 规格逐项显示 PASS / FAIL / UNKNOWN；FAIL 标原因 |
| US-06 | P0 | 作为销售，我知道下一步做什么 | 输出报价/寄样/索取规格/补证书等一项具体动作 |
| US-07 | P0 | 作为系统，我能合并重复公司 | 域名/名称/地址等证据支持的重复项合并并留审计记录 |
| US-08 | P0 | 作为销售，我能查看撮合结果 | 展示来源可验证的采购入口或公开业务联系渠道，并可记录“已跟进”状态；平台不代发消息 |
| US-09 | P1 | 作为销售，我能筛国家、产品、时间窗口 | 筛选后排序可复现，不改变原始分数 |
| US-10 | P1 | 作为演示者，我能切换缓存模式 | 页面明确标记 LIVE / CACHED / SAMPLE |
| US-11 | P0 | 作为非会员，我能预览需求但不能获取完整入口和联系方式 | 服务端返回受限字段；前端遮罩不是唯一权限控制 |
| US-12 | P0 | 作为有效会员，我能解锁一个匹配机会 | 服务端校验会员状态/额度，生成 access grant 后返回采购入口和公开商务联系方式 |
| US-13 | P1 | 作为会员，我能记录洽谈与成交结果 | 状态支持 FOLLOW_UP、NEGOTIATING、WON、LOST；失败原因可选 |

### 2.1 核心对象优先级

1. `Buyer Requirement`：平台最核心的数据资产，来自海外公开来源。
2. `Buyer Entity`：用于把需求归属到正确公司，并处理别名和母子公司。
3. `Seller Capability Profile`：卖家的私有筛选/匹配条件，不是公开商品。
4. `Opportunity`：某条买家需求相对某个卖家条件的推荐结果。

没有卖家条件时，平台仍可按需求真实性和时效展示买家需求；填写卖家条件后才增加 Fit 评分。

## 3. 四维“真实需求”证明模型

四维验真只回答“这个买家需求是否可信”，不回答“贵州卖家能否满足”。总分 `Truth Confidence` 为 0–100。

| 维度 | 权重 | 必要字段 | 计分规则（Demo 固定参数） | 反例 |
|---|---:|---|---|---|
| D1 需求明确性 | 35 | `product_terms`, `buying_action`, `specs`, `quantity`, `destination` | 产品明确 10；采购动作明确 10；规格/等级 5；数量或频次 5；目的地/交付条件 5 | 只有“关注抹茶趋势”、招聘营销人员 |
| D2 主体真实性 | 25 | `buyer_name_raw`, `canonical_buyer_id`, `domain`, `country`, `company_evidence` | 公司名 5；官网域名 7；国家/地址 5；注册号/权威目录或稳定企业页 5；可验证业务关联 3 | 无主体的论坛帖子、一次性邮箱 |
| D3 时间有效性 | 25 | `published_at`, `observed_at`, `time_precision`, `change_type` | ≤7 天 25；8–30 天 18；31–90 天 8；>90 天或未知 0 | 无日期页面、仅有多年以前进口历史 |
| D4 交叉印证 | 15 | `source_type`, `corroborating_signal_ids`, `repeat_count`, `contact_evidence` | 第二独立来源 7；90 天内重复信号 4；公开业务联系方式/采购入口 4 | 同一文章被多个聚合站转载不算独立来源 |

### 3.1 真实性分级

| 分数 | 等级 | 处理 |
|---:|---|---|
| 75–100 | A 强证据 | 可进入排序；页面突出展示 |
| 60–74 | B 可用证据 | 可进入排序；必须展示缺失字段 |
| 40–59 | C 待核验 | 不进入 Top 5，进入候选池 |
| 0–39 | D 弱信号 | 丢弃或仅保留研究用途 |

### 3.2 硬门槛

- `evidence_url`、`observed_at`、`evidence_excerpt` 任一缺失：拒绝。
- `published_at` 未知或超过 90 天：不能作为“近期窗口”主证据，但可作为背景证据。
- 已证实的认证、规格、市场准入、MOQ 等硬冲突：机会状态降为 `REJECTED_CONFLICT`。
- 无可执行下一步：不得进入最终 Top 5。

## 4. 机会排序模型

通过真实性门槛后再计算机会优先级：

```text
Opportunity Score
= 0.45 × Intent
 + 0.30 × Fit
 + 0.15 × Timing
 + 0.10 × Reachability
 - Penalty
```

| 分项 | 取值 | 来源 |
|---|---:|---|
| Intent | 0–100 | D1 需求明确性、来源强度、采购措辞、数量/规格完整度 |
| Fit | 0–100 | 买家要求与卖家能力的字段级匹配；UNKNOWN 单独扣分，不当成 FAIL |
| Timing | 0–100 | 发布时间衰减 + 是否存在近期变化/重复信号 |
| Reachability | 0–100 | 官网采购入口、公开业务邮箱、LinkedIn 公司页等；不猜测私人联系方式 |
| Penalty | 0–30 | 数据陈旧、来源低可信、实体归属不清、要求冲突、疑似转载等 |

分数只表示 Demo 规则下的销售优先级，UI 禁止写成“成交概率 82%”。

## 5. 产品/产业能力字段

### 5.1 通用品类模型

| 类别 | 字段 |
|---|---|
| 基础 | 产品形态、产地、用途、等级/质量等级原文、可供规格 |
| 商务 | MOQ、样品、价格带、币种、月产能、交期、Incoterms、OEM/ODM、私标能力 |
| 市场 | 目标国家、已有出口国家、包装语言、目标渠道 |
| 质量 | COA、批次追溯、保质期、储存条件、过敏原、第三方检测 |
| 认证 | 证书类型、证书编号、发证机构、有效期、适用产品/工厂、证据文件 |
| 准入 | 市场、要求类型、状态 `PASS/FAIL/UNKNOWN`、证据、责任方、到期日 |

平台通过 `category + product_form + attributes(JSON Schema)` 表达不同海外采购需求以及卖家的私有匹配条件。通用字段参与撮合，品类专属字段由配置定义；卖家条件只用于计算，不对买家或其他卖家公开。

### 5.2 抹茶专属字段

| 类别 | 字段例子 |
|---|---|
| 产品 | 食品配料/饮品/烘焙用途；原料茶种/采摘批次；是否遮阴；蒸青/研磨工艺 |
| 物理 | 粒径/目数、颜色或色差值、含水率、溶解/分散特征 |
| 化学 | 咖啡因、茶多酚/儿茶素、农残检测面板、重金属、污染物 |
| 微生物 | 菌落总数、酵母霉菌、大肠菌群、沙门氏菌等，按买家/目的市场要求记录 |
| 包装 | 铝箔袋/罐、净重、氮气填充、避光、防潮、散装/零售包装 |

“ceremonial grade / culinary grade”等营销等级只保存买家原文或卖家声明，不冒充统一法定等级。

### 5.3 蓝莓专属字段

| 产品形态 | 关键字段 |
|---|---|
| Fresh | 品种、果径、糖度 Brix、硬度、外观缺陷、采摘/包装日期、预冷、冷链温度、箱规、植物检疫/市场准入 |
| IQF | 品种、单果/颗粒规格、Brix、碎果率、异物、微生物、农残、包装、储存温度、冷链 |
| Dried | 含水率、水活度、糖/添加物、微生物、包装、保质期 |
| Powder/Juice | 固形物/Brix、花青素或指标成分、载体/添加物、粒径、微生物、包装 |

Demo 第二配置默认 `IQF`，但 Schema 保留 `product_form`，避免把鲜果、冻果、果粉混成同一产品。

## 6. 法规、认证与商业规格的分层

| 层级 | 示例 | 系统处理 |
|---|---|---|
| 法定准入 | 美国食品设施注册、进口商 FSVP；欧盟农残 MRL、污染物限量；有机产品相应进口证明 | `market_access_requirement`，硬条件可触发 FAIL |
| 客户指定认证 | BRCGS、FSSC 22000、ISO 22000、HACCP、Halal、Kosher 等 | `buyer_required_certification`，只有买家明确要求才设为硬条件 |
| 商业规格 | 粒径、Brix、MOQ、包装、交期、价格、冷链 | `product_requirement`，逐项 PASS/FAIL/UNKNOWN |

注意：系统只做销售前置匹配，不提供法律合规结论。具体限量值按目的国、产品类别、有效日期查询官方数据库，不能写死一个“全球通用阈值”。

## 7. 页面与主流程

### Screen 1：买家需求搜索与私有匹配条件

- 目标产品切换：抹茶 / 蓝莓（IQF）。
- 必填只有产品关键词、目标国家；规格、认证、MOQ、产能等为可选私有筛选条件。
- 这些字段不生成卖家商品页，只用于筛选和 Fit 评分。
- 缺失字段显示 UNKNOWN，不阻塞卖家先查看海外买家需求。

### Screen 2：扫描过程

- 展示 2–3 个来源、抓取状态、原始条数、清洗条数、去重条数。
- 展示数据模式：LIVE / CACHED / SAMPLE。
- 单源失败后继续使用成功来源或缓存，不显示假进度。

### Screen 3：今日 Top 5

卡片字段：买家、国家、产品、Opportunity Score、Why Now、Truth Level、Fit 摘要、最新证据日期、数据模式。

- 免费态：显示受限买家名称、国家、产品、摘要和评分；采购入口与联系方式不由接口返回。
- 会员态：可点击“解锁买家需求”；套餐有额度时按次生成访问授权。

### Screen 4：买家机会详情

- Buyer：标准公司名、域名、国家、母公司/子公司关系。
- Why Now：基于证据的 1–2 句解释。
- Evidence：URL、来源、发布时间、抓取时间、原文片段。
- Match Matrix：要求、卖家能力、状态、证据。
- Gap/Risk：未知或冲突项。
- Next Action：一项首要动作 + 可选备用动作。
- Matchmaking CTA：打开已验证的采购入口/公开业务联系渠道，并将机会状态改为 `FOLLOW_UP_STARTED`。

### Screen 5（可做弹层）：会员解锁

- 展示当前套餐、有效期、剩余额度。
- 点击解锁后由后端校验订阅，生成 `Buyer Access Grant`。
- 解锁结果返回采购入口、公开企业邮箱/联系页/采购页等 B2B 渠道及证据来源。
- 不展示私人手机号、私人邮箱或通过猜测生成的联系方式。

### 服务边界

| 阶段 | 36 小时 Demo | 赛后平台 |
|---|---|---|
| 信息聚合 | 做 | 持续增加合规数据源 |
| 需求验真 | 做 | 引入人工反馈与历史转化校准 |
| 智能撮合 | 做：根据买家需求和卖家私有条件推荐 | 用卖家反馈校准排序，不默认建设多卖家竞价市场 |
| 销售跟进 | 做最小闭环：公开采购入口/业务渠道跳转 + 状态记录 | 是否建设站内沟通必须经过买家授权和商业验证 |
| 合同/支付/订单 | 不做 | 由卖家现有销售流程处理，不属于当前产品定位 |
| 物流/报关/履约 | 不做 | 由卖家及其服务商处理，不属于当前产品定位 |
| 会员收费 | Demo 做服务端权限与预置会员；不接支付 | 赛后再接支付、发票、续费和套餐管理 |

### 7.1 会员与访问权限规则

| 规则 | Demo 参数 |
|---|---|
| 免费预览 | 每次返回最多 5 条摘要；不返回完整 `buyer_name/domain/access_channels` |
| 有效会员 | `status=ACTIVE` 且 `starts_at ≤ now < ends_at` |
| 解锁额度 | Demo 套餐 20 条/月；同一会员重复解锁同一机会不重复扣减 |
| 授权对象 | `subscription_id + opportunity_id`，生成后可重复查看 |
| 过期处理 | 已解锁记录保留；Demo 允许会员查看历史解锁 |
| 审计 | 保存解锁时间、套餐、机会、返回渠道版本，不保存支付卡信息 |

联系方式质量分级：采购表单/官方采购邮箱 > 官网公开商务邮箱/联系页 > 公司社交主页。来源失效、邮箱退信或超过复核周期时标记风险，不继续作为“已验证联系方式”。

## 8. AI 的职责边界

| AI 做 | AI 不做 |
|---|---|
| 从原文抽取产品、规格、数量、时间、国家、采购动作 | 编造原文没有的数量、联系人、认证或发布日期 |
| 把多语言原文标准化为统一字段 | 用生成内容替代证据 URL 和原文片段 |
| 对候选实体生成别名建议 | 无证据自动把母子公司合并 |
| 根据规则结果生成 Why Now / Gap / Next Action | 覆盖规则引擎的硬冲突结论 |

所有抽取返回字段必须带 `value + confidence + evidence_span`；低于阈值的字段落为 UNKNOWN。

## 9. 异常与降级

| 情况 | 行为 |
|---|---|
| 来源超时/封禁 | 标记来源失败，使用缓存；不重试轰炸 |
| LLM 超时 | 使用规则/关键词抽取和已缓存结构化结果 |
| 发布日期解析失败 | `time_precision=UNKNOWN`，不能成为近期主证据 |
| 实体去重不确定 | 不合并，进入人工复核队列 |
| 无 Top 5 | 如实显示可行动机会不足，不用弱信号补位 |
| 断网 | 切换 `CACHED` 数据集并保留完整证据快照 |

## 10. 非功能要求

- 主路径接口 P95 < 1.5 秒（爬取任务除外）。
- 列表结果固定排序：`score DESC, latest_signal_at DESC, opportunity_id ASC`。
- 每次评分保存规则版本与输入快照，保证可复现。
- 原始 HTML 不直接渲染，避免 XSS；证据片段纯文本化。
- 不存储私人联系方式；只存公开的业务联系渠道。
